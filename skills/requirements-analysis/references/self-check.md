# 交付前自检

分两类：数字类必须全过（跑脚本），判断类逐条看（人看）。判断类过不了的，写进文档而不是藏起来。

## 数字类

跑 `scripts/check_storyset.py <故事集路径>`，或手工核对：

- [ ] 卡片数 = 切片数（逐一对应，不多不少）
- [ ] 编号连续，无断号、无重号
- [ ] 每卡六个字段齐全：Title / Description / Design / Conversation / Acceptance Criteria / 元信息
- [ ] 每卡 AC 编号从 1 连续
- [ ] AC 总数与上次记录一致（批量改动后尤其重要）
- [ ] 波次分布与切片文档一致
- [ ] 规模分布一致，L 卡数量已知且都在卡内写了再拆方向
- [ ] 每条 BR / 需求 ID 至少被一张卡覆盖；无孤儿卡
- [ ] 无 `TBD` 残留（Design 字段尤其）

## 判断类 · BRD

- [ ] 每个业务目标都有现状值、目标值、期限？没有现状值的，是否已写明"降为定性目标"？
- [ ] 每个数字都标了来源（实测 / 口述 / 推断）？
- [ ] 标「推断」的内容，有没有在某处被当成事实使用？
- [ ] 每条需求都挂了业务目标？挂不上的处理了吗？
- [ ] Out of Scope 是否写到条款级（"只做 X，结论由 Y 写"）？
- [ ] 门禁清单是否逐条对应真实缺陷？有没有从教科书抄来的条目？
- [ ] AS-IS 的每个"断"都有据可查的后果？
- [ ] TO-BE 的每个检查点都有恢复条件？没有恢复条件的是不是关卡？
- [ ] 异常分支是否都有去处（回哪一步、谁决定）？
- [ ] 待确认清单分了阻塞 / 非阻塞？去重了吗？

## 判断类 · 切片

- [ ] 每片有具名 actor 和具名产物？能回答"谁拿到什么"？
- [ ] 有没有按技术层切的片（"做接口""做界面"）？
- [ ] Feature 的划分依据写清了吗？有没有解释"为什么这不是横向切分"？
- [ ] 发布单位是波次还是 Feature？如果是 Feature，纵向链路怎么保证？
- [ ] 失败路径（阻断 / 回退 / 降级）在第几波？晚于第一波的要给出理由。
- [ ] 有外部依赖的片是否单独切出，并在 AC 里兜住了数据缺失？
- [ ] 硬依赖是否显式列出，并说明是流程顺序而非切法造成？
- [ ] 每片都能写出至少 3 条 AC？（写不出的片要重切）
- [ ] 阻塞项是否转成了 TAD，每条绑定具体片与时点？

## 判断类 · 故事卡

- [ ] 每卡 Conversation 里有"决定"？没有的说明还没想过。
- [ ] 每卡 AC 覆盖了几类？缺的那类是否有理由？
- [ ] 有没有"系统应正确处理异常"这类不可验证的 AC？
- [ ] 边界类 AC 是否覆盖了空 / 缺 / 重复 / 超限 / 并发？
- [ ] 有没有把"不得"写清楚（而不是只写"应该"）？
- [ ] 有历史样本的，是否用样本做了回归基准？
- [ ] 全局约定是否抽出？有没有在每卡重复同一句？
- [ ] AC 条数与用例数的关系写了吗？
- [ ] 权限（判定 / 确认 / 签发）写进卡了吗？

## 判断类 · 呈现

- [ ] Design 字段是"屏 + 区域 + 约束"，还是 TBD？
- [ ] 线框只画了必要的几屏？列表页是否复用了组件？
- [ ] 状态表达是否脱离颜色？
- [ ] "不可用"与"0"是否可区分？
- [ ] 文档是否写明了"刻意没做的事"？
- [ ] 有没有宣称"全部就绪"？L 卡、未决问题、过渡期安排是否都标出来了？

## 最后三问

交付前对着文档问自己：

1. **这份文档里，有没有一个数字是我编的？** 有就改成"待确认"。
2. **如果评审只问一个问题，最可能问什么？** 现在能不能答上。答不上的，就是下一版要补的。
3. **如果按这份文档做完，验收时最可能被挑什么？** 挑出来的那条，现在就写进"未决"或"风险"，而不是等验收时解释。
