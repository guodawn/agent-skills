# 故事卡

每卡五段：Card / Design / Conversation / Confirmation / 元信息。

```
## US-101 新影像入库即完成四项技术质检

**Title**：影像技术质检（分辨率 / 时相 / 云量 / 投影）

**Description**：As a 遥感工程师, I want 影像一到位系统就校验四项并给出通过或不通过,
so that 我不用把整景处理完才发现这张影像不能用。

**Design**：屏 A · 影像质检表（[线框 A](线框.html#A)）｜约束：四项一行；异常行用斜纹 + 文字

**Conversation**
- **决定**：四项合成一张卡，不按项拆。四项共用同一个阻断出口和同一张质检单。
- **决定**：缺元数据判"不达标"，不判"跳过"。
- **未定**：阈值具体值待确认，本卡只锁"阈值可配 + 变更留痕"。

**Acceptance Criteria**

*可观测行为*
1. ...
*系统校验规则*
2. ...
*边界情况*
3. ...
*性能*
4. ...
*可用性*
5. ...
*集成点*
6. ...

**元信息**：覆盖 BR-001 ｜ 依赖 D1 ｜ 波次 0 ｜ 规模 S
```

## Conversation 段不是装饰

3C 里的 Conversation 指"故事是对话的占位符"。不写对话，卡就退化成需求条目，开发只能按字面实现。

每条 Conversation 归入三类：

- **决定**：已经拍板的取舍 + 一句话理由。理由要写，否则下次评审会重新讨论一遍。
- **未定**：还没定的，写清"本卡怎么兜住它"。没兜住的未定项不能进迭代。
- **风险**：这条卡已知会踩的坑。

一个可用的判断：如果 Conversation 里没有"决定"，说明这张卡还没想过，只是抄了需求。

## 六类 AC

| 类 | 写什么 | 缺了会在哪暴露 |
|---|---|---|
| 可观测行为 | 用户能看到、点到、拿到什么 | 无法演示，验收时只能靠嘴说 |
| 系统校验规则 | 判什么、判据、不满足怎么办 | 缺陷漏出——这类项目的大部分缺陷是"没校验"造成的 |
| 边界情况 | 空、缺、重复、超限、并发 | 空态崩溃、重复入库、0 记录报错 |
| 性能 | 响应时间、批量耗时、上限 | 业务目标（周期、人力）无法验证 |
| 可用性 / 可访问性 | 键盘、色觉、误操作防护 | 现场误用；判读类界面靠颜色会直接导致误判 |
| 集成点 | 与谁交换什么格式 | 交付物接不上，最后一刻才发现 |

写 AC 的三个技巧：

1. **边界类优先**。流程型项目的失败模式集中在空、缺、重复、跨期这四类。
2. **把"不得"写清楚**。"数据不足只能输出未判定，不得输出未超高"比"应正确处理缺失数据"有用一百倍。
3. **给可回归的基准数据**。有历史样本就用它当验收数据："以一期 26 个图斑为回归集，指标须与基线表逐项一致，浮点误差 ≤ 0.01"。这比任何描述都硬。

## 全局约定（G-1…G-n）

每张卡都会重复的规则，抽出来写一次，放在故事集开头。示例：

- **G-1 留痕**：所有写操作记录 操作人 / 时间 / 对象 ID / 变更前后值。
- **G-2 阻断可定位**：所有阻断给出"哪一层、哪一条、哪个对象或哪一句话"。
- **G-3 不静默**：缺数据、缺配置、跳过检查，一律显式提示，不得默认通过。
- **G-4 版本**：所有可导出物带版本号与生成时间。
- **G-5 数值**：统一小数位与单位，两种面积口径不得混用。
- **G-6 时间**：期次格式统一；工作日按法定日历。
- **G-7 权限**：判定 / 确认 / 签发分别归谁，系统不得代行。

**G-3 和 G-7 最容易被省掉，也最容易出事。** 前者决定"检查有没有出口"，后者决定"出错谁负责"。

## 规模与 AC 数量

- AC 条数随领域合规密度上升。一般产品 4–6 条，合规重的项目可到 10–13 条。
- **必须写一句"AC 条数 ≠ 用例数"**，并给出合并后的大致数量（经验值：约为 AC 数的 1/3）。不写，测试会按 AC 条数排期，然后严重高估。
- 偏离常规条数时说明理由，不要沉默地写 13 条。

## 元信息行

```
**元信息**：覆盖 BR-001 ｜ 依赖 D1、T3 ｜ 波次 0 ｜ 规模 S
```

四个字段都有用：

- **覆盖**：支撑追溯矩阵，防止孤儿卡。
- **依赖**：排期用；也是"哪张卡被卡住"的第一手信息。
- **波次**：发布单位。
- **规模**：识别还太大的卡。

## 常见错误

| 错 | 表现 | 修法 |
|---|---|---|
| AC 写成任务 | "开发接口 X" | 改写成用户可观测的结果 |
| AC 不可验证 | "系统应正确处理异常" | 换成具体判据 + 具体输出 |
| Conversation 空着 | 只有 Title 和 AC | 补"决定 / 未定"，否则说明没想过 |
| 所有卡同一个 so that | 说明只切了动作，没切价值 | 回到切片步骤重切 |
| Design 全是 TBD | 几十个占位符 | 改成"屏 + 区域 + 约束" |
| 只写正常路径 | 没有边界与异常 | 每卡至少 2 条边界 |
