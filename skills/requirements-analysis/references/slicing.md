# 故事切片

拆分是分解能力，不是写作能力。写故事的技能默认你已经知道要写哪个故事；切片的技能解决的是"该切几刀、切在哪"。

## 八种模式在流程型项目的落点

按顺序试，命中一个就停。

| 模式 | 用在哪 | 例 |
|---|---|---|
| 1 工作流步骤 | 一条链上的先后环节 | 校验 → 阻断与人工决定 → 处理 |
| 2 业务规则变体 | 同一动作下的不同规则，各自独立可测 | 三条预检规则各一片；门禁按检查对象分组 |
| 3 数据变体 | 输入/输出类型不同，失败后果不同 | 有图斑 vs 空图层；变化指标 / 风险指标 / 辅助统计 |
| 4 AC 复杂度 | 一张卡里出现多组 When/Then | 自校的多条判定；门禁的十条检查 |
| 5 主要工作量 | 某部分的技术量级明显高一个档 | 需要解析文档的检查 vs 纯结构化检查 |
| 6 外部依赖 | 依赖外部数据/第三方，且可能长期不到位 | 依赖外部数据源的能力单独切 |
| 7 DevOps | 有独立部署单元时才用 | 无部署单元就不要硬套 |
| 8 TAD | 未知太多，先做小实验 | 阻塞项转先行验证 |

## 流程型项目的默认切法

```
Feature = 流程阶段（S1..Sn + 跨期域）
Story   = 阶段内可独立验收的最小片
发布单位 = 波次（纵向薄切片）
```

**为什么 Feature 按阶段分不算横向切分**——这一条必须在文档里论证，否则评审会打回。

- 横向切分的定义是**按技术层切**（前端/后端、模型/界面、数据处理/文档生成），产物谁也用不了。
- 这里 Feature 只是 **backlog 的组织单位**：每个阶段的验收人、验收物、失败后果都不同，混在一起排期会失真。
- **纵向由波次保证**：每个波次从各阶段各取最薄一片，串成一条能跑通的链路。

判断一片是不是横向切：问"这一片单独拿出去，有哪个具名角色能拿到具名产物？"答不上来就是横向切。

## 波次切法

四波，逐层加厚。

| 波次 | 目的 | 取哪些片 | 出门条件 |
|---|---|---|---|
| 0 骨架 | 证明链路通、阻断有效 | 每个阶段取 1–2 片最薄的 | 一份内部版产物 + 一次真实触发的阻断 + 一次真实留痕 |
| 1 正式 | 让质量目标成立 | 补齐校验、留痕、门禁、版本 | 已知缺陷类型归零 |
| 2 深化 | 让闭环成立 | 依赖外部数据的、跨期的 | 上一期的问题在本期有回应 |
| 3 体验 | 提升效率与体验 | Could 级 | 不影响前三个波次的承诺 |

**失败路径必须在波次 0/1**：阻断、回退、降级。理由不是"重要"，是"缺陷漏出往往不是因为没检查，是因为检查没有出口"。把阻断放到第三波，前两波交付的就是"有检查但没人管"。

## 四条反模式

| ❌ | 为什么不行 |
|---|---|
| 按系统模块切（数据处理 / 文档生成 / 模型推理 / 工单） | 每片都不产生可交付物。这正是现状里"交接断"的成因，用切法把它复制一遍 |
| 按前端 / 后端切 | 界面没有数据，模型出来没人看 |
| 一条需求一片 | 需求不是价值单位。一条需求里常含 5 项校验、10 条门禁，一条一片等于没拆 |
| 一条数据一片 | 数据行不是故事。它们走的是同一条代码路径 |

## 切完怎么验证

四问，答不上就重切：

1. 每片都有具名 actor 和具名产物？
2. 每片能独立测试？（能构造数据、能写出 Given/When/Then）
3. 每片规模在一次迭代内？
4. 合起来等于原 Feature？（用追溯矩阵逐条核对，不能有孤儿片）

**反向验证最有效**：给每一片试着写 3 条 AC。写不出来的片，说明它不是一个独立的价值单元，回去合并或重切。

## 规模标记

`S` ≈ 1–2 天 ／ `M` ≈ 3–4 天 ／ `L` ≈ 5 天以上，**进迭代前必须再拆**。

只用相对标记，不写点。分母（真实人日）没测出来之前，任何精确到点的估算都是编的。L 卡要在卡内直接写明"建议按什么维度再拆"。

## TAD：切片前先解未知

阻塞项不是"待补充信息"，它们直接改变某些片的做法。先做小实验，再进开发。

| 列 | 内容 |
|---|---|
| 未知 | 一句话 |
| 影响的片 | 具体 ID，不要写"多个" |
| 怎么解 | 实验/书面确认/试算，写清产物 |
| 时点 | 最晚什么时候要有结论 |

最贵的两类：**能不能无人值守调用**（决定自动化承诺是否成立）、**外部数据能否到位**（决定能力是否可上线）。这两条要在波次 0 之前有答案。

## 依赖处理

流程型项目的片之间必然有顺序依赖（阶段二依赖阶段一的产物）。这不违反"独立"，但要显式处理：

- 在切片文档里列"刻意保留的硬依赖"，说明是流程顺序而非切法造成。
- 波次按依赖顺序排，不硬凑并行。
- 外部依赖造成的"不够独立"要用 AC 兜住：把"数据缺失时只能输出什么"写成可测条件，这样即使数据没到也能上线验收。
